      How the correction works

      1. Bleedover. Each cluster is a colony of copies of one DNA molecule. Its dye light spreads over a few pixels, so a cluster's measured RFU also contains light from neighbours. Crowded clusters look brighter than they are.
      2. Simulate. From every cluster's position and brightness, the app renders the image the camera should see, using a point-spread function learned from isolated dots.
      3. Fit. It adjusts each cluster's brightness until the simulated image matches the real one. Every photon then belongs to exactly one cluster. Corrected RFU stays on the Feather scale.

      Terms

      RFU
      MAPA's per-cluster intensity. Relative: compare only within one experiment.
      Calibration
      counts = gain × RFU + offset: turns this experiment's RFU into camera counts.
      Zero light
      The RFU a cluster with no dye of its own gets after correction (−offset / gain). Blank subtraction removes it.
      R²
      1 − (what the simulation leaves unexplained ÷ the real image's variation). 1 = the simulated image matches every pixel; it can never exceed 1. It is negative when the simulation is worse than a flat image at the average brightness, as before correction: Feather RFU already contains neighbours' light, so rendering it adds that light twice and the simulated image is far too bright.
      Normalized SD
      SD of one sequence's replicate clusters ÷ their mean: how much copies of the same molecule disagree, independent of how bright they are.
      Trusted cluster
      Inside the image and ≥ 100 px inside the area MAPA's cluster table covers.
